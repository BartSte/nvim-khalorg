*khalorg.txt*  Neovim interface for khalorg

REQUIREMENTS                                                    *khalorg-requirements*

Neovim 0.11 or later, nvim-orgmode with its Org parser, and configured khalorg
and khal executables on PATH. Orgmode installs its parser during setup.

CONFIGURATION                                                   *khalorg-setup*
>
    local khalorg = require('khalorg')
    khalorg.setup({ calendar = 'my_calendar' })
    require('orgmode').setup({
      org_custom_exports = {
        n = { label = 'Add a khal event', action = khalorg.new },
        e = { label = 'Edit a khal event', action = khalorg.edit },
        E = { label = 'Edit dates too', action = khalorg.edit_all },
        d = { label = 'Delete a khal event', action = khalorg.delete },
      },
    })
<
setup() and setup({}) select the default calendar. Public functions also work
before setup. Calendar names must contain at least one non-space character.

CALENDAR MAPPINGS                                               *khalorg-calendars*
>
    require('khalorg').setup({
      calendar = 'personal',
      executable = 'khalorg',
      calendars = {
        personal = { org_file = '~/org/personal.org' },
        work = { org_file = '~/org/work.org' },
      },
    })
<
Actions use the calendar mapped to the current file. Other files use calendar.
An explicit action option, such as edit({ calendar = 'work' }), overrides this
selection. Each file can map to only one calendar. Paths expand ~ and resolve
existing symbolic links. executable selects the khalorg executable.

USAGE                                                           *khalorg-usage*

Place the cursor inside an Org event. Use the orgmode export menu (<leader>oe),
or call require('khalorg').new(), .edit(), .edit_all(), or .delete() directly.
edit_props() is an alias for edit(). No exporter callback is required.

Place one active timestamp directly below the headline. A single SCHEDULED or
DEADLINE timestamp also works. Explicit Org ranges and repeaters remain intact.
Multiple independent active timestamps are rejected. Inactive timestamps do
not define event dates. Child sections do not enter the export.

Edits and deletion require an existing UID property. edit() updates properties
and the description. edit_all() also updates dates and recurrence. Deletion
removes a whole recurring series.

SYNC                                                            *khalorg-sync*

:KhalorgSync [calendar]          Sync a whole Org file with khal.
:KhalorgSyncDryRun [calendar]    Preview changes without applying them.

Commands require setup(). Calendar names support completion. The file mapping
supplies the calendar and path. Without a mapping, the current named .org file
is used. Save changes before sync. Clean buffers reload after sync. Edits made
during sync remain in the buffer, with a message about disk changes.

Sync runs asynchronously and opens a results buffer. Overlapping operations
for the same calendar or file are rejected. Missing CLI support produces an
upgrade message. Remote CalDAV synchronization still requires vdirsyncer.

Global sync options and per-calendar sync overrides accept start (today),
stop (90d), conflict_resolution (khal or org), edit_dates (false),
delete_on_sync (false), state_dir (khalorg default), and filetags (a tag list).
Use sync(opts) or sync_dry_run(opts) for Lua overrides. on_complete(result)
receives the process result. sync_dry_run() always enables the preview.

Khalorg owns UID matching, conflicts, and persistent sync state. Keep its state
files between runs. Sync can rewrite the Org file using khalorg's event format.
Deletion propagation is disabled by default. Preview changes before enabling
delete_on_sync, which propagates deletions between sources.

LIST AND IMPORT                                                 *khalorg-list*

:KhalorgList [calendar] [start] [stop]    Open events in a separate Org buffer.
:KhalorgCalendar                        Select a calendar, then list events.
:KhalorgImport [calendar] [start] [stop]  Write events to a new mapped Org file.

The default range comes from the sync configuration (today through 90d).
Calendar names and common ranges support command completion. Escape spaces in
command arguments with a backslash. List preserves source files and unsaved
edits. Save the list buffer with :write /path/to/calendar.org.

Import refuses to overwrite existing files. Use sync for existing files.
Lua equivalents are list(opts) and import(opts), with calendar, start, stop,
and org_file options. on_complete(result, bufnr) receives the process result
and any preview buffer.

CUSTOM EXPORTS                                                  *khalorg-make_exporter*
>
    local show_event = require('khalorg').make_exporter({ 'cat' })
    show_event()
<
Commands run asynchronously without a shell. Pass an argument array, not a
shell string. Event text passes directly through stdin.

get_item_in_fold_under_cursor() returns event text or an empty string without
an active timestamp. Invalid or ambiguous selections raise an error. Public
actions report these errors through Neovim messages.

HEALTH                                                          *khalorg-health*

:checkhealth khalorg checks Neovim, orgmode, the Org parser, khalorg commands,
khal, optional vdirsyncer, and mapped directories. CLI probes have a
five-second timeout. Health checks do not change calendar data.
